# Rakia AI Server

Standalone Node.js server that powers the RAK Airport chatbot "Rakia". Host it on
**your own server** (e.g. the Jenkins host / any Linux VM). The website — hosted
anywhere — calls this API over HTTP. Answers are strictly grounded in the site's
own content (`site-knowledge.json`), using the free Groq API.

## Requirements
- Node.js 18 or newer (has built-in `fetch`). No `npm install` needed — zero dependencies.
- `site-knowledge.json` next to `rakia-server.mjs` (generated by `npm run build` in the main project).

## Run
```bash
GROQ_API_KEY=gsk_your_key ALLOW_ORIGIN=https://www.rakairport.com HOST=127.0.0.1 PORT=3001 node rakia-server.mjs
```
- `GROQ_API_KEY` — your key from https://console.groq.com/keys (kept server-side, never sent to browsers).
- `PORT` — default 3001.
- `ALLOW_ORIGIN` — permitted browser origin. Defaults to `https://www.rakairport.com`.
- `HOST` — bind address. Defaults to `127.0.0.1`; leave this unchanged in production so IIS is the only public entry point.
- `MAX_BODY_BYTES`, `MAX_MESSAGE_CHARS`, `RATE_LIMIT_MAX`, and
  `RATE_LIMIT_MAX_BUCKETS` — optional request safety limits. The bucket cap
  defaults to 10,000 and expired entries are evicted automatically.
- `TRUST_PROXY` — keep unset unless the reverse proxy first removes incoming
  `X-Forwarded-For` and adds the verified client address itself. Set it to
  `true` only after that proxy configuration is in place.

## Keep it running (pick one)

**pm2**
```bash
npm i -g pm2
GROQ_API_KEY=gsk_xxx pm2 start rakia-server.mjs --name rakia-ai
pm2 save && pm2 startup
```

**systemd** (`/etc/systemd/system/rakia-ai.service`)
```ini
[Unit]
Description=Rakia AI Server
After=network.target

[Service]
WorkingDirectory=/path/to/server
Environment=GROQ_API_KEY=gsk_your_key
Environment=PORT=3001
Environment=ALLOW_ORIGIN=https://www.rakairport.com
Environment=HOST=127.0.0.1
ExecStart=/usr/bin/node rakia-server.mjs
Restart=always

[Install]
WantedBy=multi-user.target
```
```bash
sudo systemctl enable --now rakia-ai
```

## Expose it through IIS only
The production website proxies same-origin `/chat` to `http://127.0.0.1:3001/chat`
using ARR. Do not add a public firewall or DNS rule for port 3001.
The browser only communicates with the public HTTPS website; IIS handles the
private loopback connection to Node.

## Endpoints
- `GET /health` → `{"ok":true}` (local process check only)
- `POST /chat` → body `{"messages":[{"from":"user","text":"parking rates?"}]}` → `{"text":"..."}`

## Updating content
When the site content changes, re-run `npm run build` in the main project and copy
the fresh `server/site-knowledge.json` to this server (restart if needed).
